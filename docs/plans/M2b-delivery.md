## 1. 现在能做什么

1. **启动秒开**：库里有 5000 条时，卡片 28ms 灌进内存，第一次 `files:list` 18ms 返回，不用等 readdir + stat。
2. **项目归属**：建「春季海报」这类项目（可挂客户名），在右侧详情面板给稿件指定；客户只读、随项目带出。
3. **标签**：详情面板回车加标签、`×` 删除，带已有标签补全；卡片上压最多 2 个 chip（超出 `+N`），信息卡不显示标签。
4. **目录自动打标签**：设置页配「监听目录 → 标签」，之后进这个目录的新稿自动带标签；手动改过的不回弹，最长前缀优先。
5. **改名 / 同盘移动不丢标签**：按 `dev:ino` 认身份，沿用数据库旧行的 id；标签、项目、缩略图全跟着走，100 个批量改名零重解。
6. **三件套筛选**：项目 + 标签 + 时间，与类型 / 目录 / 关键词 / 排序自由组合，命中数实时显示。
7. **误移出目录可找回**：文件离开监听目录只标 `missing_at`，移回来标签仍在；30 天后才真删。
8. **坏库自愈**：启动自检不通过就备份坏库、重建，并从 `index.db.meta.json` 快照把标签 / 项目 / 规则 / 归属捡回来。

## 3. 关键实现决定

### 3.1 内存 Map 仍是唯一真相，库只做「秒开 + 认身份」

5000 条 `ProjectFile` 约 2MB，全量下发渲染端 2.1MB、过滤 2ms 级。所以没有上 SQL 下推、分页窗口、worker 过滤 ——
那些是为 2 万以上准备的复杂度，5 千量级只会让滚动和筛选更难写。

### 3.2 身份 = `dev:ino`，path 兜底

`stat(full, { bigint: true })` 取 NTFS 的 64 位 ino，转字符串存 TEXT。number 版会丢精度，两个不同文件可能撞同一身份，
进而把 A 的标签贴到 B 上。三步匹配：身份命中 → 沿用旧 id 只改路径；path 命中 → 跨盘/重装更新身份；都没有 → 新行套自动规则。

### 3.3 缩略图键也换成身份

`sha1(version|size|mtime|dev:ino)`。改名不改 ino、mtime，所以 100 个批量改名直接命中旧缓存；
用户点刷新也不会因为"路径变了"重解一遍。

### 3.4 缺失判定用「本轮扫到的路径集合」

原计划用 `last_seen < scanToken`，但那意味着每轮要给 5000 行各写一次 UPDATE，
二次启动就不满足「零变更零写库」。改成收尾时拿扫描路径集合与库里活行做差集，只写真正消失的行。

### 3.5 元数据快照兜底极端损坏

坏库如果只是某页坏了，`salvage()` 还能直接从坏库读 tags 表；整库被截断时读不出来。
所以标签 / 项目 / 规则 / 文件归属每次变更 150ms 后另存一份 `data/index.db.meta.json`（原子替换），
重建时作为最后一道防线。标签是这里唯一「重扫扫不回来」的数据。

### 3.6 标签挂 `files.id`，不挂 path

`file_tags` 是 `on delete cascade`。任何「删旧行 + 插新行」的写法都会在改名时静默清空标签，
所以三步匹配命中后只 UPDATE 路径，id 原样沿用。

## 4. 与计划的偏差

| 计划 | 实际 | 原因 |
|---|---|---|
| 逐文件串行 `stat` | 同目录内 32 路并发 | 实测串行冷扫 1469ms 超 1s 口径；并发后 965ms |
| `last_seen < scanToken` 判缺失 | 本轮路径集合做差集 | 前者每轮写 5000 行，违背「零写库」验收 |
| 坏库自检在打开之后 | 自检提前到设 pragma 之前 | 坏库连 `PRAGMA journal_mode=WAL` 都抛错，自愈分支根本走不到 |
| `untagged: boolean` + `tagId` 双状态 | `tagId = -1` 表示无标签 | 一个数字字段表达三种状态，筛选条少一个开关 |
| 只从坏库抢救标签 | 增加 `index.db.meta.json` 快照 | 截断库连 tags 表都读不出来，实测会丢标签 |
| `bumpLastSeen` 心跳 | 删除 | 路径集合方案不再需要 |

## 5. 已知限制

- **跨盘复制不继承标签**（dev 变、path 也变，按新文件处理）；同一块盘内改名 / 移动没问题。
- `ino=0` 的文件系统（部分网络盘 / 移动硬盘）退化为 path 匹配，改名会丢标签。
- 标签筛选是单选；多选、父子标签、智能文件夹在 P2。
- 时间视角（年月分组 / 时间轴）、Ctrl+F、批量操作、改名 / 删除 / 打开器联动都不在本阶段。
- 项目 / 标签删除是物理删除，没有回收站；删标签会级联清掉所有文件上的该标签。
- `node:sqlite` 在开发模式实测可用；M4 打包成 asar 后必须再验一次，降级路径是 `better-sqlite3`（改动只在 `db/index.ts`）。
